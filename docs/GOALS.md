# Goals

Jelly goals are persistent objectives with an actual Pi continuation loop, not a todo list. Open **Goals** (target icon) beside any agent's options, including newly created agents. Save an objective and a positive **parent-session continuation token budget**, then choose **Resume goal** to authorize autonomous execution. Saving does not call a model. Browser disconnection does not stop execution; Jelly must remain running.

## Behavior

- One current goal per Jelly agent, independent of cwd and Pi session identity. States: `paused`, `active`, `blocked`, `budget_exhausted`, `completed`; clearing retains a `cleared` archival record but removes the current goal.
- Edit only while stopped with no admitted goal run. Editing preserves goal identity, all usage, and progress, and leaves the goal stopped. An open editor pins its create/edit operation, goal identity and base revision. Live refreshes or conflicts never silently rebase the draft onto changed/replaced goals; cancel and reopen the editor explicitly to load the current goal. Completion evidence likewise pins its original goal and revision; refresh/conflict never retargets old evidence. Clear the evidence to explicitly start a new draft. Completed goals are immutable except Clear. Clear before creating a replacement; wait for any old goal run to finish first.
- Resume requires an idle, unarchived agent with no pending human messages and remaining budget. It uses normal Jelly admission, current agent settings/context and the existing single-active-run constraint. There is **no hidden wait queue or retry timer**. Busy conflicts are visible; unavailable credentials persist a blocked reason. Resolve the issue and explicitly resume.
- Every normal action-capable Pi request gets one current goal system envelope through `context_with_system`, including ordinary tool follow-ups, human steering, native idle child wakes and requests after compaction. It supplies full active objective/progress, exhausted wrap-up guidance, or stopped instructions rather than historical authority. Pi's leading prompt and tool declarations remain intact; only Jelly-owned historical goal sections and continuation/budget messages are filtered from the request view, not durable history. At `agent_before_settle`, the extension adds one custom context draft and requests exactly one further turn, only if the bound execution is active, successful, has budget, has no queued messages/other continuation and has no active or unknown owned child work. Native child completion/heartbeat notifications remain the sole child wake source. Lost completion reconciliation retains the terminal job until its notice is actually consumed by Pi; its in-flight parent response remains tracked for safe settlement but does not itself block the next goal continuation. Other live/unknown children and unconsumed notices still block continuation. The goal never relaunches a child automatically.
- `jelly_goal` is registered only in a goal's parent session. `get` inspects state; `progress`, `block`, and `complete` require a nonempty summary (completion should include requirement-by-requirement verification evidence). The tool cannot create, resume, edit the objective, or increase budgets. Ordinary child missions remain package-owned recovery records, never mirrors of Jelly goals.
- Completion requires the explicit tool or operator action. A finished run or final assistant answer is **not** completion. Model completion is an attestation, **not an independent verification**. A genuine blocker can be reported immediately; Jelly does not impose Codex's prompt-level three-turn blocker audit.
- At most **32 automatic goal continuations per resume**. This safety limit blocks with a visible reason, never marks success. Explicit resume resets the continuation count, not usage. Normal Jelly 1,000-turn/five-hour limits also apply; goals never evade them by silently starting another run.
- Errors and unexplained settlement block the goal. Human queue/steering input fences execution authority, giving the human priority: active goals become paused; exhausted goals remain visibly exhausted but lose the admitted run's completion exception without resetting budget or usage. Afterward, resume explicitly. Existing schedules share normal run admission; a goal will not displace a running schedule, and a schedule will not overlap an active goal run.

### Pause versus Stop

Pause, Complete and Clear fence future **goal-generated** continuations. They do not roll back files, retract already-admitted context/requests, abort tools, or kill children. The panel separately displays **work still running**, with **Stop agent**. A boundary continuation already committed before a pause is admitted work, not a retractable message. Native queued notifications and tool follow-ups may still finish; there is no competing goal wake queue.

**Stop** fences the goal before aborting the normal parent/child lifecycle (pausing active goals, retaining exhausted state and usage). A later callback cannot reactivate it. Objective edits are prohibited until admitted work finishes, avoiding mixed objective snapshots. Fresh Session preserves goals and usage; it does not resume stopped goals. Archive is allowed only after work stops and cannot silently reactivate goals on restore.

### Restart safety

Graceful shutdown pauses active goals before cancellation. On process restart, previously running Jelly runs become interrupted and every active goal becomes paused with an uncertainty warning. Even activation committed just before a crash requires explicit resume. **No accepted tool/request is automatically replayed.** Review potentially completed external effects and retained child records before resuming. Paused, blocked, exhausted and completed goals remain stopped. This conservative policy deliberately differs from Codex's active-goal reload behavior.

## Budget semantics — not a spend ceiling

The label is **parent-session continuation token budget**, not total goal cost. For each finalized parent assistant message in the bound Jelly run:

```text
charged tokens = Pi usage.input + Pi usage.cacheWrite + Pi usage.output
```

Pi 0.87.1 normalizes those components separately. Its OpenAI Responses adapter subtracts cache reads **and cache writes** from provider input before populating `usage.input`; the Anthropic adapter uses separate input/cache-creation fields. Cache writes are therefore added once. Cache reads are excluded. `totalTokens`, cost estimates and reasoning subtotals are not added again. This approximates Codex's uncached-input-plus-output semantics using Pi's normalized fields, rather than subtracting cache reads twice.

- Counts are cumulative across resume, budget edits, compaction and Fresh Session. Only bound goal-run parent messages count; unrelated later human/schedule runs do not. Parent messages arriving after pause/clear/complete are still charged to their original goal, not a replacement.
- A `(runId, persisted message entryId)` ledger deduplicates accounting. Usage, transcript, checkpoint and resulting exhaustion state/events commit in the same SQLite transaction. Failed/aborted messages count any reported components too.
- **Excluded:** delegated child model tokens, automatic compaction, agent naming, nested tool/provider calls (including image generation), external CLI work and other uninstrumented calls. Child usage is not claimed as zero; it is explicitly **outside this budget**. There is no total-spend meter or descendant reconciliation in this version.
- Missing/invalid numeric parent usage marks the count as a **lower bound** and blocks active continuation. Explicit resume after inspection is possible; the unknown flag remains visible. Providers can return zero placeholders (especially failed requests), which cannot be distinguished from real zero usage. Unreported usage before a process crash cannot be recovered. Other provider adapters are trusted to honor Pi's normalized usage contract.
- Once observed usage reaches/exceeds budget, `budget_exhausted` persists immediately and no new goal continuation is admitted. At the next `turn_end` the extension appends one wrap-up instruction **without requesting another model turn**. Already-admitted tool follow-ups/native child wakes see “no new substantive work; summarize progress/remaining scope.” Actual verified completion can still be reported by the same admitted execution until human input, Stop, shutdown or an operator mutation fences its authority; exhaustion alone is never success.
- This is a **soft continuation budget, not a hard token or dollar cap**. In-flight requests, admitted tool loops and native child notifications may overshoot; child work is not killed based on a parent-only budget. The wrap-up instruction is model guidance, not a sandbox or provider-side reservation. Use Stop for strong cancellation. No promises are made about rollback or exact spend.

## Implementation and API

`src/server/goals.ts` owns state transitions. SQLite schema v18 adds `agent_goals`, `goal_runs` (immutable objective/budget snapshot per execution epoch), `goal_usage`, and `goal_mutations`. `src/server/goal-extension.ts` is an actual inline Pi extension passed through `DefaultResourceLoader.extensionFactories`. It is **not installed in shared Pi settings**, so detached children do not inherit a Jelly goal owner. No package-owned mission files or installed modules are changed.

Initial/resumed goal execution is admitted with the normal Jelly transaction before any provider/tool work. Identity + execution epoch fences model mutations and continuation. A successful model progress update does not change the epoch; operator changes invalidate it. The durable unique `(goalId, epoch)` admission and normal run uniqueness prevent duplicate execution. Goal events publish after commit, appear outside collapsed generic work in the conversation, and use the existing authenticated resumable SSE/snapshot refresh path. The modal refreshes from authoritative reads on snapshot invalidation rather than adding a polling loop. Full objectives are not copied into every-agent sidebar snapshots. The panel serializes/coalesces reads across SSE invalidations, mutation/conflict responses and Stop. Reads spanning a mutation are discarded; one fresh read after settlement resolves ordering, including a GET intent arriving after POST but before commit. Delayed mutation bodies never overwrite a newer view; failed requests retain pinned drafts and retry IDs.

Pi's standalone compaction provider calls bypass normal context hooks. `session_before_compact` adds a bounded current goal snapshot to each nonempty history/split-turn preparation span, preserving Pi's summarizer, other extensions' data and cut points. This is summarization context, **not authorization to act**. A pause during summarization may make that snapshot historical; the next normal request always rereads durable authority.

Compatibility boundary: the request-envelope guarantee uses Pi's normal structured-prompt path. In installed 0.87.1, an extension forcing the entire system prompt (`before_agent_start.systemPrompt` / `forceSystemPrompt`) is projected **after** context hooks and discards sections. Do not combine such extensions with goal mode. Jelly blocks goal continuation with a visible reason when a preceding forcing extension is detected, without rewriting its prompt or aborting already-admitted work. A later forcing handler or arbitrary trusted context rewrite cannot be made safe by this adapter; no private host patch/provider wrapper is installed. Jelly itself does not force prompts.

All routes share Jelly's control-cookie, CSRF and same-origin enforcement:

| Method | Route | Body / result |
| --- | --- | --- |
| GET | `/api/agents/:agentId/goal` | `{goal, runningRunId}` |
| POST | `…/goal/create` | `{requestId, objective, tokenBudget}`; creates paused |
| POST | `…/goal/edit` | `{requestId, goalId, expectedRevision, objective, tokenBudget}` |
| POST | `…/goal/pause`, `…/goal/resume`, `…/goal/clear` | `{requestId, goalId, expectedRevision}` |
| POST | `…/goal/complete` | same plus nonempty `summary` |

All mutation responses are the current `{goal, runningRunId}` view. Stable request IDs deduplicate identical mutations; changed payload reuse and stale revisions return 409. Replaying a successful Resume never launches again, even after the original run finishes. Wrong agent-goal membership returns 404. Unknown/server-owned fields are rejected. Objectives/summaries are bounded to 16,000 characters, request IDs to 100; budgets are positive safe integers. No model credentials are required for CRUD. The existing 64 KiB request limit applies. There is no new global goals page, multi-goal planner, execution-history API or time budget; normal conversation history and the durable ledger retain evidence.

## Research and reuse decision

Research was supplied from pinned upstream source inspection, not inferred from plugin names or an old local Codex checkout.

- **Codex** reference: [`openai/codex@0ddee3e1d898f7823df97e9aaf08b420be51c804`](https://github.com/openai/codex/tree/0ddee3e1d898f7823df97e9aaf08b420be51c804), a researched main revision, **not a released-version compatibility claim**. Key sources: [`spec.rs`](https://github.com/openai/codex/blob/0ddee3e1d898f7823df97e9aaf08b420be51c804/codex-rs/ext/goal/src/spec.rs), [`continuation.md`](https://github.com/openai/codex/blob/0ddee3e1d898f7823df97e9aaf08b420be51c804/codex-rs/ext/goal/templates/goals/continuation.md), [`budget_limit.md`](https://github.com/openai/codex/blob/0ddee3e1d898f7823df97e9aaf08b420be51c804/codex-rs/ext/goal/templates/goals/budget_limit.md), [`accounting.rs`](https://github.com/openai/codex/blob/0ddee3e1d898f7823df97e9aaf08b420be51c804/codex-rs/ext/goal/src/accounting.rs), [`runtime.rs`](https://github.com/openai/codex/blob/0ddee3e1d898f7823df97e9aaf08b420be51c804/codex-rs/ext/goal/src/runtime.rs). Jelly adopts one persistent objective, explicit status, cumulative usage, automatic idle continuation and audited completion guidance. It does **not** claim Codex parity for child accounting, automatic restart, blocker audits or provider usage-limit classification.
- **Installed pi-subagents 0.71.0** ([mission docs at its revision](https://github.com/nicobailon/pi-subagents/blob/4af5e85a427b9f87334585ae8d0eb365d4dd2a1e/docs/missions.md)): inspected installed `docs/missions.md`, `src/missions/goal-driver.js`, `src/extension/control-notices.js`. Goal notices use `triggerTurn: details.source === "async"`; goal source is `"goal"`, so native mission goals **do not trigger another turn**. Ownership is Pi-session/project scoped; budget sums linked children, not parent work. No public host mission-management API solves Jelly's per-agent lifecycle. Keep the existing mission/run ledger for delegated-work recovery unchanged, rather than using it as an incompatible goal runtime.
- Existing dedicated plugins were researched: [`pi-goal@0.1.7`](https://github.com/Michaelliv/pi-goal/tree/3f100be5434454d3388755a119d01caca9127c16) has a real follow-up loop but cache-inclusive accounting, weaker cancellation and old namespace peers. [`@astrosheep/pi-goal-next@0.2.6`](https://github.com/astrosheep-zero/pi-goal-next/tree/f82e160832af2eddaa1b8178dd7f15e4f398dac6) has useful journaling/fencing ideas; it documents Pi ≥1.1.0 and reads `agent_settled.aborted`, absent from Jelly's 0.87.1 host. That is an abort-semantics mismatch, not necessarily a load-time failure.
- **[`@fyeeme/pi-goal@1.0.6`](https://registry.npmjs.org/@fyeeme/pi-goal/-/pi-goal-1.0.6.tgz)** is the strongest reuse candidate: it uses the same actionable `agent_before_settle` boundary and the same `input + cacheWrite + output` arithmetic. Its declared Pi ≥0.99.0 peer alone does not establish incompatibility. Its session-branch persistence, broader assistant/tool/compaction accounting and fallback follow-up ownership do not replace Jelly's per-agent durable admission, web idempotency, explicit restart authorization and native child-wake owner. Its evaluator completes when unavailable, and its subprocess resolver can select Jelly's server entrypoint rather than Pi. Those ownership and evaluator risks—not version numbers alone—justify retaining Jelly's small inline adapter. Focused request-context hygiene and boundary draft composition are adopted without importing another scheduler/evaluator.
- `pi-goal-x@0.34.1` adds a larger workspace multi-goal pool, scheduler and audit owner, also reading newer `agent_settled.aborted`; its input/output formula omits separately normalized cache writes. **No new dependency or host upgrade**, independent verifier or stagnation detector. No upstream prompt/source code is copied wholesale.
- Installed Pi **0.87.1** documentation and examples: complete `docs/sdk.md`, `docs/extensions.md`; SDK examples `01-minimal.ts` through `13-session-runtime.ts`; linked extension examples `hello.ts`, `todo.ts`, `dynamic-tools.ts`, `truncated-tool.ts`. Exact boundary contracts checked in `dist/core/extensions/types.d.ts` and `dist/core/agent-session.js`. The supported actionable hook is `agent_before_settle`, not notification-only `agent_settled` or premature `agent_end`. Normalized usage verified in `@earendil-works/pi-ai/dist/api/openai-responses-shared.js` and `anthropic-messages.js`.

## Validation and remaining limits

`bun run test:goals` exercises migration/reopen, per-agent isolation, strict fields, durable replay/revisions, usage dedupe/rollback, actual installed Pi continuations and tools with deterministic local providers, exhaustion/overshoot/wrap-up, 32-continuation breaker, pause/clear/complete races, Stop, human priority, simultaneous agents, fresh-session/archive, shutdown, API security, client editing/conflicts/stale navigation, concurrent edit and clear/replacement fencing, and SIGKILL recovery without replay. Integrated `goal-extension.test.ts` tests combine real Pi boundaries, goal tools and SessionWork lost-completion reconciliation, including queued versus consumed notices, repeated refreshes, previous observation failure and another live child. Correctness regressions additionally cover every-request authority after pause/clear/steering, exhausted takeover/Stop/shutdown completion fences, preceding extension drafts at both boundaries, request-only history hygiene, actual manual and automatic split-turn compaction, pause during summarization, native idle wakes with ordinary tool follow-ups, forced-prompt compatibility, completion-draft replacement/objective edits and both HTTP response orderings (including conflict/Stop reads). Tests do not run real user goals or paid provider calls.

Trusted extensions/tools still have broad host permissions. Prompt rules (blocker judgement, verification, budget wrap-up, avoiding duplicate native mission goals) are not independent enforcement. Existing ambient goal plugins could compete; do not install another goal driver for the same work. Child reconciliation relies on the existing SessionWork lifecycle; a goal that settles unexpectedly becomes blocked rather than guessing or relaunching work. There is no exact total cost cap, automatic host wake, external-effects rollback, or independent completion verifier. Real-provider accounting and visual mobile/browser behavior require deployment-specific smoke validation; no live Jelly server restart or hosting change is part of this implementation.
