# Phase 4 — Native macOS application

- [ ] Wrap the web workspace in a native macOS application and bundle or manage its Bun server and runtime dependencies.
- [ ] Implement installation, startup, shutdown, updates and platform-appropriate data locations.
- [ ] Integrate access to local and saved remote instances into the native client.
- [ ] Add native notifications and platform credential storage where useful.
- [ ] Decide how to provide the managed browser/computer capability on macOS, then implement and verify that platform integration.
- [ ] Verify installation, upgrades, server recovery and data preservation on a clean Mac.

## Exit criteria

Users can install and launch Jelly like a normal Mac app, connect to local or remote instances, and upgrade without manually managing a server or losing data.
